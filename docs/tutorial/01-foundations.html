先补齐推理系统的基础词汇

如果 token、tensor、head、logits、Prefill 这些词还不熟，不要跳过这一页。后续所有源码，本质上都在搬运这些对象。

1. 从文本到 Token ID

神经网络不能直接接收汉字或英文字符串。Tokenizer 按自己的词表规则把文本切成 token，再把每个 token 映射成整数 ID。

简化示例（数字仅用于讲解）
“KV Cache 很快”
→
[“KV”, “ Cache”, “ 很”, “快”]
→
[8132, 447, 109, 281]

注意：token 不等于汉字，也不等于单词。它是 tokenizer 词表里的一个片段。项目的稳定 runtime 从 token ID 开始；文本编码/解码仍由外部 tokenizer 完成。

2. Tensor 与 Shape

Tensor 可以先理解为“带形状的多维数组”。在代码里，shape 比变量名更能说明数据是什么。

符号含义示例
Bbatch size，同时处理的请求数3 个请求 → B=3
Ssequence length，token 数量prompt 有 8 token → S=8
Hhidden size，每个 token 的内部向量宽度Qwen2.5-0.5B 常见 H=896
Hq/HkvQuery head / KV head 数量GQA 中 Hq 可以大于 Hkv
D每个 attention head 的维度D = H / Hq = 64
Vvocabulary size，词表大小logits 最后一维
读 shape 的方法

hidden_states [B,S,H] 表示：B 个请求，每个请求 S 个 token，每个 token 用 H 个浮点数表示。

query [B,Hq,S,D] 表示：把 hidden 维拆成 Hq 个注意力头，每个头宽 D。

3. 模型不是“输出文字”，而是输出 Logits

模型最后输出 [B,S,V] 的 logits。对每个位置，它为词表里的每个 token 给出一个未归一化分数。Greedy decoding 直接选择最大分数的 token：

next_token = argmax(logits[:, -1, :], dim=-1)

token 42

logit = 1.2

token 99

logit = 4.8 ← 最大

token 105

logit = −0.3

所以本项目的生成策略很简单：每一步取 argmax。它没有 temperature、top-k 或 top-p。

4. Prefill 与 Decode 为什么要分开

PrefillDecode
输入完整 prompt：[B,S]上一步生成的 1 个 token：[B,1]

生成 N 个新 token 最多只需要 N−1 次 Decode。最后一个 token 已经输出给用户，不会再作为输入计算，所以 Cache 最大长度是 prompt_length + max_new_tokens − 1。

5. Attention 最小直觉

每个 token 会产生 Q（我想找什么）、K（我能被怎样匹配）、V（匹配后拿走什么信息）。当前 Query 对历史所有 Key 打分，再用 softmax 得到权重，加权求和历史 Value。

scores = Q × Kᵀ / √D
probabilities = softmax(scores)
output = probabilities × V
生活类比

Query 像搜索词；Key 像每篇文档的索引；Q·K 是相关度；softmax 把相关度变成总和为 1 的权重；Value 是最终读出的文档内容。

检查：为什么 Decode 只需要计算新 token 的 Q/K/V？
历史 token 的 K/V 在它们第一次计算时已经保存到 KV Cache。新 Query 仍需读取全部历史 K/V，但不必重新计算历史 token 的投影。

逐函数拆解 Qwen ModelRunner

这一页对应 qwen_model_runner.py。目标不是推导所有数学证明，而是能看懂每个函数接收什么 shape、做了什么、为什么这样排序。

1. 顶层 Prefill 调用链

input_ids[B,S]
→
Embedding[B,S,H]
→
24 × Decoder[B,S,H]
→
Final RMSNorm[B,S,H]

x = F.embedding(input_ids, self.weights.embedding)
for layer_index, layer in enumerate(self.weights.layers):

@torch.inference_mode() 关闭 autograd：推理不需要保存反向传播中间量，能减少显存和框架开销。

2. Embedding：ID 变向量

Embedding 矩阵 shape 是 [V,H]。F.embedding 本质上按 token ID 选行，不是矩阵乘法。

玩具例子：V=5, H=3
embedding = [
  [0.1, 0.2, 0.3],  # token 0
  [0.7, 0.0, 0.4],  # token 1
  ...
]
input_ids = [[1, 0]]
output = [[[0.7,0.0,0.4], [0.1,0.2,0.3]]]  # [1,2,3]

3. 一层 Decoder 的两条残差支路

输入 x[B,S,H]
RMSNorm → Attention结果与原 x 相加（第一条 residual）
RMSNorm → SwiGLU MLP结果再与 residual 相加
输出[B,S,H]
residual = x
x = _rms_norm(x, input_norm, eps)
x = residual + _attention(x, ...)

residual = x
x = _rms_norm(x, post_attention_norm, eps)
gate = F.silu(F.linear(x, gate_weight))
up = F.linear(x, up_weight)
x = F.linear(gate * up, down_weight)
return residual + x
i

Residual 让每个子模块学习“对现有表示的修正”，并给深层网络提供稳定的信息通道。两次赋值 residual = x 对应两条不同的残差支路。

4. RMSNorm：只看均方根

rms = sqrt(mean(x²) + ε)
normalized = x / rms
output = weight × normalized
dtype = x.dtype
x_fp32 = x.float()
normalized = x_fp32 * torch.rsqrt(
    x_fp32.pow(2).mean(-1, keepdim=True) + epsilon
)
return weight * normalized.to(dtype)

中间转 FP32 是为了减少半精度求平方、均值、倒平方根时的数值误差；最后再转回输入 dtype。

5. Q/K/V Projection 与多头 reshape

线性层先输出扁平的最后一维，再由 _heads() 拆成 head，并把 head 维移到 sequence 前面：

[B,S,Hq×D] → reshape [B,S,Hq,D] → transpose → [B,Hq,S,D]
对象Projection 后拆 head 后
Q[B,S,H][B,Hq,S,D]
K[B,S,Hkv×D][B,Hkv,S,D]
V[B,S,Hkv×D][B,Hkv,S,D]

GQA：为什么 Q head 比 KV head 多？

Grouped Query Attention 让一组相邻 Query heads 共享一个 KV head，以减少 Cache 大小和读取量。

Hq=8, Hkv=2

group_size = 8/2 = 4。Q heads 0–3 使用 KV head 0；Q heads 4–7 使用 KV head 1。

kv_head = query_head // group_size

6. RoPE：把位置信息旋转进 Q/K

纯 Attention 不知道 token 顺序。RoPE 为每个位置生成 cos/sin，用二维成对旋转作用到 Q 和 K。V 不做 RoPE。

frequencies = position_ids * inv_freq
cos, sin = frequencies.cos(), frequencies.sin()
query = query * cos + rotate_half(query) * sin
key   = key   * cos + rotate_half(key)   * sin
!

Decode 新 token 的 position 不是 0，而是追加前的 Cache 长度。若历史长度是 17，新 token 的 position 必须是 17。

7. Attention 两条路径

Torch / Prefill

连续数学路径

必要时 repeat K/V，再算完整 scores。Prefill 使用 causal mask，禁止位置 i 看未来位置 j>i。

scores = Q @ K.transpose(-2,-1) / sqrt(D)
scores = scores.masked_fill(future, min_value)
prob = softmax(scores, dtype=float32)
per_head = prob @ V
Paged CUDA / Decode

物理块路径

query length 必须为 1。K/V 先写入 pending slot，kernel 用 block table 直接遍历历史，不 gather 连续副本。

inputs = cache.paged_attention_inputs(layer)
per_head = paged_decode_attention_cuda(
    query[:, :, 0, :],
    inputs.key_cache,
    inputs.value_cache,
    inputs.block_table,
    inputs.sequence_lengths,
)

8. Decode 为什么包含“当前 token 自己”

Decode 的输入 token 是上一步已经选出的 token。它先产生当前 token 的 K/V 并写入 Cache，然后当前 Q 可以注意包括自己在内的完整前缀。因此：

position_id = old_cache_length
attention_sequence_length = old_cache_length + 1

这是项目里最常见的 off-by-one 风险。position 用于 RoPE；sequence length 用于 Paged Attention 读多少 K/V，它们不能共用同一个数。

检查：为什么 Prefill 需要 causal mask，而单 token Decode 不需要显式 mask？
Prefill 同时包含多个位置，必须禁止早期位置看到后面的未来 token。Decode 只有序列末尾的一个 Query，它面对的 Cache 全部是允许看到的过去和当前 token，所以无需再构造 mask。

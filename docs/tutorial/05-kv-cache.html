Chapter 05 · KV Cache

为什么要缓存 K/V，以及怎样安全地写

KV Cache 是推理引擎最核心的状态。它让 Decode 不再反复计算历史 token，但也引入容量、生命周期和失败一致性问题。

1. 没有 Cache 会重复多少工作

prompt=[A,B,C]，准备生成 D、E、F
步骤无 Cache有 Cache
生成 D计算 A B CPrefill A B C
生成 E重新计算 A B C D只计算 D，读取缓存 A B C
生成 F重新计算 A B C D E只计算 E，读取缓存 A B C D

历史 token 的 hidden state 会随层变化，但在自回归 causal attention 中，历史 token 对应的 K/V 不会因后续 token 到来而改变。因此可以逐层保存。

2. 连续 KV Cache 的物理布局

key/value shape = [layer, batch, kv_head, capacity, head_dim]
维度含义
layer每个 Decoder layer 有自己的 K/V
batch当前固定 batch 的请求行
kv_headGQA 的 K/V head
capacity预分配的最大 token 数
head_dim每个 head 的向量宽度

项目同时分配 key 和 value 两个 tensor，所以字节数：

storage_bytes = 2 × L × B × Hkv × capacity × D × bytes_per_element
i

Q 不需要持久化。未来 Decode 只需要“当前 token 的 Q”去查询“所有历史 K/V”；历史 Q 不会再次使用。

3. 为什么不能写一层就增加 length

一个 token 要在所有层产生 K/V。假设写到第 17 层异常：如果全局 length 已经加 1，读取者会认为 24 层都拥有这个 token，但后 7 层仍是未初始化内存。

begin_append(1)length 不变
→
write_layer 0…23写 pending 区间
→
commit_append()length + 1

事务的三个动作

begin

验证容量，创建 PendingAppend(start,end)，但不修改 length。

write

逐层写 [B,Hkv,Snew,D]，用 bool 数组记录哪些层已写。

commit / abort

全部层完成才推进 length；失败则丢弃可见性，旧字节以后覆盖。

4. 对照源码看事务

def begin_append(self, token_count):
    end = self.length + token_count
    if end > self.capacity:
        raise RuntimeError("容量不足")
    self._pending = PendingAppend(self.length, end)
    self._written_layers = [False] * self.num_layers

def write_layer(self, layer_index, key, value):
    pending = self._require_pending()
    token_slice = slice(pending.start, pending.end)
    self.key[layer_index, :, :, token_slice, :].copy_(key)
    self.value[layer_index, :, :, token_slice, :].copy_(value)
    self._written_layers[layer_index] = True

def commit_append(self):

5. ModelRunner 如何使用这个接口

cache.begin_append(sequence)
try:
    for layer_index, layer in enumerate(weights.layers):
        x = _decoder_layer(..., cache=cache, layer_index=layer_index)
        # _attention 内部调用 cache.write_layer(layer_index, K, V)
    cache.commit_append()
except Exception:
    if cache.pending is not None:
        cache.abort_append()
    raise

Runner 只依赖 LayerKVCache Protocol，而不绑定具体实现。这使相同的模型代码既能接连续 Cache，也能接 Paged Cache adapter。

6. 容量为什么是 prompt + new − 1

prompt 长 4，max_new_tokens=3

Prefill 写 4 个 token，并输出第 1 个新 token。为了输出第 2 个 token，要 Decode 第 1 个新 token（Cache 变 5）；为了输出第 3 个，要 Decode 第 2 个（Cache 变 6）。第 3 个输出后停止，不再写入。因此所需容量是 4+3−1=6。

检查：abort 时为什么不用把已写字节清零？
正确性依赖逻辑 length，而不是显存内容是否为零。abort 后这些位置不可见；下一次写同一区间会覆盖旧字节。清零只会增加无意义的显存带宽。

模型如何从磁盘变成可计算的 Tensor

这一章沿着 load_qwen_checkpoint() 往下走：先读结构配置，再读 safetensors，最后把几百个字符串 key 变成强类型的层级对象。

1. 模型目录里有什么

config.json

描述模型结构：hidden size、层数、attention heads、RoPE 参数等。它像“建筑图纸”。

*.safetensors

真正的浮点权重。它像“建筑材料”。大模型可能拆成多个 shard。

index.json

分片索引：每个权重 key 在哪个 shard 文件中。单文件模型可以没有。

model_dir/
├── config.json
├── model.safetensors                 # 单文件情况
# 或
├── model.safetensors.index.json      # 分片索引
├── model-00001-of-00002.safetensors
└── model-00002-of-00002.safetensors

2. QwenConfig：只保留 runtime 真正需要的字段

QwenConfig 是冻结 dataclass。它不是照搬 Hugging Face 的所有字段，而是显式列出当前 Runner 支持的最小结构。

@dataclass(frozen=True)
class QwenConfig:
    vocab_size: int
    hidden_size: int
    intermediate_size: int
    num_hidden_layers: int
    num_attention_heads: int
    num_key_value_heads: int
    max_position_embeddings: int
    rms_norm_eps: float
    rope_theta: float
    hidden_act: str
    tie_word_embeddings: bool
字段决定什么代码中的派生量
hidden_sizetoken 内部表示宽度 Hhead_dim = H / Hq
num_attention_headsQuery head 数 HqQ projection 输出 Hq×D
num_key_value_headsKV head 数 Hkvgqa_group_size = Hq/Hkv
intermediate_sizeSwiGLU 中间层宽度gate/up projection 输出
num_hidden_layersDecoder 重复层数Cache 第一维和层循环
vocab_size词表大小 VEmbedding 行数、logits 最后一维

4. state_dict 为什么还要映射成 QwenWeights

原始 state_dict 是 dict[str, Tensor]。字符串灵活，但容易拼错，也不表达层级关系。项目把它转换成：

QwenWeights
├── embedding
├── layers: tuple[DecoderLayerWeights, ...]
│   ├── input_norm
│   ├── attention
│   │   ├── q_proj / k_proj / v_proj / o_proj
│   ├── post_attention_norm
│   └── mlp
│       ├── gate_proj / up_proj / down_proj
└── final_norm

内部的 take(name, shape) 同时完成三件事：要求 key 存在、要求 shape 正确、记录该 key 已被消费。

def take(name, shape):
    if name not in state_dict:
        raise KeyError(f"缺少权重：{name}")
    tensor = state_dict[name]
    if tuple(tensor.shape) != shape:
        raise ValueError("shape 不匹配")
    consumed.add(name)
    return tensor
Q projection 的 shape 为什么是 [H,H]？

输入 hidden state 最后一维是 H。Qwen 的 Q 有 Hq 个 head，每个 D 维，且 Hq×D=H，所以输出仍是 H。PyTorch F.linear(x, weight) 的 weight 布局是 [out_features,in_features]，因此是 [H,H]。

K/V 输出只需要 Hkv×D，所以 shape 是 [Hkv×D,H]。

5. Tied Embedding 是什么

Embedding 把 token ID 查表变成 hidden vector；LM Head 把 hidden vector投影回词表 logits。当前 Qwen 配置让两者共享同一张矩阵：

embedding: token_id → embedding_weight[token_id]
lm_head: logits = hidden × embedding_weightᵀ

如果 checkpoint 同时提供 lm_head.weight，代码要求它与 embedding 数值相同，否则报错。这避免“配置说共享，权重却不共享”的不一致。

检查：为什么最后还要拒绝 unexpected keys？
如果加载后还有未消费的权重，可能说明 checkpoint 模型变体与当前实现不同，或者映射漏了层。忽略它们会让“不完整实现”悄悄运行。

Appendix · Glossary

术语表与 Shape 速查

阅读源码时遇到不熟悉的词，可以随时回到这里。

核心术语

Token
Tokenizer 词表中的基本片段，用整数 ID 表示，不一定等于字或单词。
Tensor
带 dtype、device 和 shape 的多维数组；PyTorch 模型数据的基本载体。
Embedding
按 token ID 从 [V,H] 权重矩阵查行，得到 token 的 H 维向量。
Hidden State
模型内部每个 token 当前的向量表示，通常 shape [B,S,H]。
Logits
词表每个 token 的未归一化分数，最后一维是 V。
Greedy Decoding
每步直接选择 argmax token 的生成策略。
Prefill
一次处理完整 prompt，建立 K/V Cache 并产生首 token。
Decode
每次只处理一个新 token，复用历史 K/V，产生下一个 token。
Attention
用 Q·K 相似度形成权重，再对 V 加权求和的机制。
Q / K / V
Query、Key、Value；由 hidden state 经过不同线性投影得到。
Head
把 hidden 维分成多个独立注意力子空间。
GQA
Grouped Query Attention；多个 Query heads 共享较少的 KV heads。
RoPE
Rotary Position Embedding；把位置通过旋转编码进 Q/K。
RMSNorm
基于均方根的归一化，不减均值。
SwiGLU
Qwen MLP：SiLU(gate projection) × up projection，再 down projection。
KV Cache
持久保存各层历史 token 的 K/V，避免 Decode 重算历史。
Block
Paged KV 的固定大小物理分配单元，包含 block_size 个 token slots。
Block Table
单请求的逻辑 block index 到物理 block ID 的映射。
Internal Fragmentation
已分配 block 最后未使用的 token slots。
Pending
已经分配/写入但尚未 commit、对普通读取不可见的 token 区间。
Transaction
begin→write→commit/abort 的原子可见性协议。
Scheduler
维护请求状态并决定当前 step 执行哪些 Prefill/Decode 的控制面。
Admission
接纳 waiting 请求进入 running 前的资源检查和 block 预留。
Continuous Batching
每个 step 允许完成请求离开、新请求补入，batch 动态变化。
Static Batching
本项目指 no-refill cohort：当前 cohort 未排空时不接纳新请求。
CTA
CUDA Cooperative Thread Array，即一个 thread block。
Online Softmax
边扫描 score 边更新 max/sum/output，不物化完整 attention vector。
D2H
Device to Host；GPU 数据同步回 CPU。
TTFT
Time To First Token：arrival 到第一个 token 可见。
TPOT
Time Per Output Token：相邻输出 token 的 ready 时间差。
E2E
End-to-End：arrival 到最后 token 可见。
Oracle
用于定义正确答案的可信 reference，本项目主要使用 Hugging Face 显式 forward。

最后的自检清单

  • 能解释为什么第一个输出 token 来自 Prefill logits
  • 能解释生成 N 个 token 为什么最多 Decode N−1 次
  • 能从 token index 算出 physical block 和 offset
  • 能区分 RoPE position 与 Attention sequence length
  • 能解释为什么 commit 必须等全部层完成
  • 能解释 batch row 顺序为什么是安全契约
  • 能描述 Scheduler、Engine、Runner、Manager 的职责边界
  • 能区分 correctness reference、kernel benchmark 和端到端 benchmark

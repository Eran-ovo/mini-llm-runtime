Prefill 与 Decode

同一个 Decoder，两种完全不同的工作负载。Prefill 一次吞下整段 prompt；Decode 每个请求只推进一个 token，并复用此前的 KV。

07 · Mental Model

必须守住的契约

理解这六条，基本就抓住了整个项目最容易出错、也最有价值的部分。

① Batch row 绝不能乱

token、position、Q/K/V、block table 和 length 的第 i 行必须属于同一 request。

② position ≠ read length

Decode position 是 old_len；当前 K/V 写入后 Attention 读取 old_len + 1。

③ 可见长度最后提交

24 层和 LM Head 都成功后才 commit；失败则所有请求一起回滚。

④ 最后输出不进 Cache

生成 N 个 token 最多只 Decode N−1 次，因此 capacity = prompt + N − 1。

⑤ Length 决定访问边界

block table 可能含 padding 或未来预留块，CUDA kernel 只能按 sequence length 访问。

⑥ Scheduler 不拥有显存

它只发完成事件；Engine/Admission Controller 才调用 manager 释放物理 blocks。
